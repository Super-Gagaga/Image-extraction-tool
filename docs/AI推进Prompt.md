# 抠图工具 AI 推进 Prompt

> 使用方式：将本文档中“主 Prompt”整体复制给编码 AI。  
> 配套文档：`docs/抠图工具技术设计文档.md`  
> 目标：让 AI 按可验证的阶段持续推进项目，直到交付可运行的 Windows 本地抠图工具。

> 当前进度：M5（智能抠图）已完成。M1～M5 已完成，边缘优化属于 M6 后续工作。

## 一、主 Prompt

```text
你是一名资深 Python 桌面应用、数字图像处理和计算机视觉工程师。请在当前仓库中持续开发一款 Windows 本地智能抠图工具。

项目的正式技术规范位于：

docs/抠图工具技术设计文档.md

开始工作前，必须完整阅读该文档，并检查仓库当前状态、已有代码、测试、依赖和未提交修改。不得覆盖或删除用户已有成果。若实现与文档冲突，以文档为准；若文档没有规定，选择结构清晰、可测试、可维护的实现。

一、最终目标

交付一款可以本地运行的 Windows 桌面抠图工具，支持：

1. 导入 PNG、JPG、JPEG、WEBP 图片；
2. 棋盘格透明背景预览；
3. 一键智能抠图；
4. 选取色块并按容差移除背景；
5. 抠除画笔和恢复画笔；
6. 1～200 原图像素画笔，最小支持真正的 1px 编辑；
7. 滚轮缩放、右键拖动平移；
8. 撤销、重做、原图对比；
9. 羽化、收缩、扩张等基础边缘优化；
10. 导出与原图尺寸一致、带 Alpha 通道的 PNG；
11. 图片默认不上传，模型在本地运行；
12. 智能推理和大图处理不能阻塞界面。

交互决策：不实现单独的“确认抠除”按钮。编辑结果始终实时显示，用户通过“导出 PNG”输出当前结果。

二、强制架构约束

1. 使用 Python、PySide6、Pillow、OpenCV 和 ONNX Runtime；自动抠图通过可替换的 Segmenter 接口接入。
2. 原始图片加载后必须保持不可变。禁止在已经透明化的预览图上反复处理。
3. AI 蒙版、颜色蒙版、抠除蒙版和恢复蒙版必须独立保存，尺寸必须与原图一致。
4. 预览图只是一份渲染缓存，任何状态变化都从不可变原图和当前蒙版重新合成。
5. 所有画笔与选区坐标必须从画布坐标转换到原图坐标。
6. 画笔大小使用原图像素，不得使用屏幕显示像素代替。
7. 快速拖动画笔时必须在相邻采样点之间插值，不能出现断点。
8. 选取色块、抠除画笔、恢复画笔是互斥工具模式。
9. 右键只负责平移，不能触发擦除、恢复或取色；左键执行当前工具。
10. 清空颜色选择与清空画笔修改必须相互独立。
11. 模型推理、模型加载和大图导出必须进入工作线程，并通过信号更新 UI。
12. 预览可以降采样，但最终导出必须使用原图和全尺寸蒙版重新合成。
13. 不得为了通过测试而删除、弱化或跳过真实功能。
14. 不得提交占位按钮、无实现菜单、伪进度或硬编码演示结果。
15. 不要增加“确认抠除”按钮；“导出 PNG”是唯一的最终输出操作。

三、工作方式

请自主推进，不要在每个普通技术决策上停下来询问。只有在以下情况才向用户提问：

- 两种方案会造成明显不同的产品行为，并且技术文档没有给出依据；
- 需要用户提供模型文件、授权、付费服务或外部凭据；
- 操作可能删除、覆盖用户文件或产生不可逆影响；
- 当前环境存在无法通过代码绕开的外部阻塞。

每轮工作按以下顺序执行：

1. 检查仓库状态和相关文件；
2. 说明本轮要完成的具体可验收目标；
3. 实现一个闭环功能，不要同时铺开大量半成品；
4. 添加或更新测试；
5. 运行与改动风险相匹配的测试；
6. 检查界面交互、错误路径和资源释放；
7. 汇报已完成内容、验证证据、剩余问题和下一步。

若测试失败，先定位根因并修复，不要绕过测试。若发现现有实现偏离技术文档，应优先修正底层状态模型，再继续堆叠新功能。

四、阶段计划

严格按照以下阶段推进。当前阶段没有达到完成定义时，不得宣称该阶段完成。

阶段 0：仓库初始化与工程基线（已完成）

目标：建立可运行、可测试、可打包的工程骨架。

任务：

- 建立 src 布局和 Python 包；
- 添加 pyproject.toml；
- 建立 ui、application、domain、infrastructure 分层；
- 建立 tests/unit、tests/integration、tests/ui；
- 添加程序入口；
- 添加日志与统一异常类型；
- 添加开发环境和运行说明；
- 创建最小主窗口，但不添加无行为的假功能。

完成定义：

- 可以通过标准命令启动主窗口；
- 测试命令可以运行；
- 包结构、依赖和入口清晰；
- 没有导入错误和未处理启动异常。

阶段 1：图片文档与画布（已完成）

目标：可靠加载、显示和浏览图片。

任务：

- 实现 ImageDocument 和 ViewState；
- 导入常见图片格式并统一转为 RGBA；
- 使用 QGraphicsView/QGraphicsScene 显示图片；
- 绘制棋盘格透明背景；
- 实现滚轮指针中心缩放；
- 实现右键拖动平移；
- 实现适应窗口和 100% 显示；
- 在状态栏显示尺寸与缩放比例；
- 为无效图片和损坏图片提供错误提示。

完成定义：

- 图片加载后原始尺寸和颜色正确；
- 多次缩放、平移不会修改图片数据；
- 右键平移不触发任何编辑；
- 坐标转换存在单元测试。

阶段 2 / M2：蒙版内核与手动画笔（已完成）

目标：完成可控、像素准确的手工抠图闭环。

任务：

- 建立 AI、颜色、抠除和恢复蒙版；
- 实现统一蒙版合成器；
- 实现抠除画笔；
- 实现恢复画笔；
- 支持 1～200 原图像素画笔；
- 实现画笔插值；
- 仅刷新受影响区域或使用安全的预览刷新方案；
- 实现清空画笔修改；
- 实现透明 PNG 导出。

完成定义：

- 1px 画笔在多种缩放倍率下位置准确；
- 快速拖动无断点；
- 右键平移不会误擦除；
- 恢复画笔可以找回被擦除像素；
- 导出 PNG 的尺寸和 Alpha 与预览一致。

阶段 3 / M3：颜色选取与容差抠除（已完成）

目标：完成纯色或近似纯色背景的交互式抠除。

任务：

- 实现选取色块工具；
- 支持左键单击取色；
- 支持拖动框选并提取区域内多种代表色；
- 悬停时显示颜色色块、RGB 和 HEX；
- 建立可见的已选颜色列表；
- 支持移除单个已选颜色和清空全部颜色；
- 实现颜色容差参数；
- 参数变化后实时刷新；
- 保持颜色蒙版和画笔蒙版互不影响。

完成定义：

- 选取色块模式下左键能够正确取色；
- 拖动框选可以产生去重后的多色选择；
- 悬停信息中的颜色色块、RGB 和 HEX 与原图像素一致；
- 已选颜色可以单项移除或全部清空；
- 画笔模式下左键不能触发取色；
- 清空已选能够恢复相应原始像素；
- 清空颜色选择不会清除画笔结果；
- 多次调整容差不会在旧预览上累积损坏。

阶段 4 / M4：撤销、重做与编辑历史（已完成）

目标：所有主要编辑操作都可以可靠恢复。

任务：

- 实现命令栈；
- 支持笔画、取色、删除颜色、参数修改、清空蒙版和应用 AI 蒙版的撤销重做；
- 一整条鼠标笔画只形成一个历史命令；
- 控制历史数量和内存占用；
- 新操作后正确清空重做栈。

完成定义：

- 至少支持 50 步常规编辑历史；
- 撤销和重做后的预览与内部蒙版一致；
- 大图笔画历史不使用无上限的整图复制；
- 后台任务失败不会写入半完成命令。

阶段 5 / M5：智能抠图（已完成）

目标：接入可替换的本地自动抠图能力。

任务：

- 定义并实现 Segmenter 接口；
- 接入一个可本地运行的 ONNX 抠图模型或 rembg 适配器；
- 处理模型输入缩放、归一化和输出恢复；
- 输出与原图尺寸一致的灰度蒙版；
- 在工作线程中加载模型和推理；
- 支持进度、忙碌状态、取消和错误恢复；
- 缓存模型会话；
- 将 AI 蒙版接入统一合成流程；
- 保证手动画笔可以修复 AI 误删和漏删区域。

完成定义：

- 推理时主窗口保持响应；
- 取消任务不会破坏当前文档；
- 模型缺失或加载失败时，手动工具仍可使用；
- AI 结果可撤销、重做；
- 输出蒙版尺寸、类型和方向正确。

阶段 6：边缘优化（后续）

目标：改善发丝、商品边缘和背景残色。

任务：

- 实现羽化；
- 实现蒙版收缩和扩张；
- 实现小孔洞修复；
- 添加可选边缘去色；
- 参数变化时提供可控预览；
- 恢复默认设置；
- 对半透明边缘保留灰度 Alpha。

完成定义：

- 羽化不会把整张主体明显模糊；
- 收缩和扩张的方向符合 UI 文案；
- 边缘去色可以关闭，且不会永久修改原图；
- 导出结果与全尺寸处理一致。

阶段 7：质量、性能与发布（后续）

目标：形成可交付的 Windows 应用。

任务：

- 完善异常处理和日志；
- 优化预览缓存和局部刷新；
- 验证大图内存占用；
- 添加 UI 自动化测试；
- 准备测试素材和视觉回归结果；
- 使用 PyInstaller 打包；
- 验证全新 Windows 环境启动；
- 编写 README、安装、模型管理和故障排查说明。

完成定义：

- 核心自动化测试全部通过；
- 常见图片流程不存在崩溃和状态错乱；
- Windows 构建产物可以启动并完成导入、编辑、导出；
- 模型文件缺失时提示明确；
- 发布包中不包含无关缓存、测试输出或用户图片。

五、测试要求

不能只运行语法检查或只测试单个函数。除单元测试外，必须通过真实 Qt 鼠标事件验证以下流程：

1. 模式切换；
2. 1px 连续画笔；
3. 画笔快速移动插值；
4. 右键平移且不擦除；
5. 缩放后的坐标映射；
6. 抠除与恢复；
7. 颜色选择和画笔的独立清空；
8. 撤销与重做；
9. 推理任务取消和错误恢复；
10. PNG 尺寸、RGBA 模式和 Alpha 内容。

视觉测试至少覆盖：

- 人物发丝；
- 白色商品和白色背景；
- 带孔洞物体；
- 半透明材质；
- 绿色背景但主体含绿色；
- 已带透明通道的 PNG；
- 8K 或其他大尺寸图片。

六、代码质量要求

1. 类型标注覆盖核心公开接口。
2. UI、领域逻辑和模型推理不得耦合在单个大文件中。
3. 核心算法必须可以脱离 GUI 测试。
4. 公共接口和非显然算法需要简短文档说明。
5. 不要使用宽泛的异常捕获隐藏错误。
6. 临时文件、线程和模型会话必须正确释放。
7. 不要将绝对路径、个人目录或测试图片路径写死在代码中。
8. 不要在仓库中提交模型权重，除非项目明确要求且许可证允许。
9. 新依赖必须说明用途，并固定合理版本范围。
10. 修改前检查工作区，保留与本任务无关的用户改动。

七、阶段汇报格式

每次完成一个开发闭环后，按以下格式汇报：

本轮结果
- 用一句话说明已经可以做到什么。

完成内容
- 列出实际实现的功能和关键文件。

验证证据
- 列出执行的测试命令、通过数量和关键人工/视觉检查结果。

已知限制
- 只列出真实存在的问题，不要把未做功能包装为已完成。

下一步
- 给出下一个最小可验收目标。

如果当前阶段尚未满足完成定义，必须明确标记“阶段未完成”，并继续修复或说明确切阻塞原因。不得仅因代码可以启动就宣称功能完成。

八、立即开始

现在请执行以下操作：

1. 完整阅读 docs/抠图工具技术设计文档.md；
2. 检查仓库结构、Git 状态、Python 环境和已有依赖；
3. 判断项目当前处于哪个阶段；
4. 选择距离当前状态最近的一个最小可验收目标；
5. 直接实现、测试并汇报结果；
6. 在安全且不需要用户选择的情况下，继续推进下一项工作，不要停留在只给计划。
```

## 二、单阶段推进 Prompt

当不希望 AI 一次推进整个项目时，可以使用下面的模板，只让它完成一个阶段。

```text
请阅读 docs/抠图工具技术设计文档.md 和 docs/AI推进Prompt.md，并只推进阶段【填写阶段编号和名称】。

要求：

1. 开始前检查当前代码和未提交修改；
2. 列出该阶段的完成定义；
3. 实现一个完整闭环，不留下占位按钮或伪实现；
4. 添加单元测试、集成测试或必要的真实 GUI 事件测试；
5. 运行测试并修复失败；
6. 未达到完成定义时不得声明阶段完成；
7. 完成后按“本轮结果、完成内容、验证证据、已知限制、下一步”格式汇报；
8. 不要改动与该阶段无关的用户文件。

现在直接开始检查和实现。
```

## 三、修复问题 Prompt

发现交互或图像结果异常时，使用下面的 Prompt。

```text
请诊断并修复当前抠图工具中的以下问题：

【填写复现步骤、预期结果和实际结果】

修复要求：

1. 先复现问题并定位根因，不要立即猜测式修改；
2. 检查是否违反不可变原图、独立蒙版、原图坐标或工具互斥原则；
3. 添加一个修复前会失败、修复后会通过的回归测试；
4. 涉及鼠标交互时使用真实 Qt 事件序列测试；
5. 涉及图像结果时检查像素、Alpha、尺寸和视觉输出；
6. 不要通过禁用功能、放宽断言或吞掉异常来规避问题；
7. 修复后运行相关测试，并说明根因、改动和验证证据。
```

## 五、使用建议

1. 新项目第一次开发时使用“主 Prompt”。
2. 希望控制改动范围时使用“单阶段推进 Prompt”。
3. 出现坐标、蒙版、恢复失败或模式冲突时使用“修复问题 Prompt”。
4. 所有功能基本完成后使用“发布验收 Prompt”。
5. 每轮都要求 AI 给出实际测试证据，不接受“理论上可行”作为完成依据。
6. 若 AI 中途只输出计划，可再次要求它遵守“立即开始”部分，直接实施当前最小可验收目标。
