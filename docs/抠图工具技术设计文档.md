# 本地智能抠图工具技术设计文档

> 文档版本：1.0  
> 目标平台：Windows 10/11  
> 产品形态：离线桌面应用  
> 技术路线：Python、PySide6、Pillow、OpenCV、ONNX Runtime

## 1. 文档目的

本文档定义本地智能抠图工具的产品范围、系统架构、核心数据模型、图像处理流程、交互规范、模块接口、测试策略及交付计划，可作为开发、测试和后续迭代的统一依据。

工具的核心目标是让用户通过“一键智能抠图 + 手动精修”获得可直接使用的透明背景 PNG，同时保证全部图片在本地处理，不依赖云端服务。

## 2. 建设目标

### 2.1 核心目标

1. 支持人物、商品、动物以及纯色背景图片的主体提取。
2. 提供自动抠图、颜色选取、抠除画笔和恢复画笔四类操作。
3. 支持像素级精修，最小画笔尺寸为 1 个原图像素。
4. 支持缩放、平移、原图对比、撤销和重做。
5. 导出与原图尺寸一致、包含 Alpha 通道的 PNG 文件。
6. 模型推理和大图处理期间保持界面可响应。
7. 默认离线运行，图片不上传到第三方服务器。

### 2.2 非目标

首个版本暂不包含以下能力：

- 用户账户、云端同步和在线素材库；
- 多人协作；
- 视频逐帧抠图；
- PSD 等专业分层格式导出；
- 模型训练与在线微调；
- 移动端版本。

## 3. 典型使用场景

### 3.1 人像抠图

用户导入人物照片，执行智能抠图，通过恢复画笔修复发丝或衣物区域，最后进行轻度羽化并导出透明 PNG。

### 3.2 商品抠图

用户导入商品图，自动获得主体蒙版，通过边缘收缩消除白边，检查透明背景后导出电商素材。

### 3.3 纯色背景抠除

用户使用“选取色块”点击背景颜色，调节颜色容差并实时查看结果，必要时使用画笔清理残留区域。

### 3.4 像素级精修

用户放大图片，以 1～5 原图像素画笔修整模型遗漏的小区域；缩放不会改变画笔在原图中的实际尺寸。

## 4. 功能范围

### 4.1 文件操作

- 通过文件选择器打开图片；
- 将图片拖入窗口完成导入；
- 支持 PNG、JPG、JPEG、WEBP；
- 支持另存为透明 PNG；
- 导出前显示路径、图片尺寸和预计文件类型；
- 当原图尚未加载时，禁用编辑和导出操作。

不设置单独的“确认抠除”按钮。画布始终展示当前蒙版的实时结果，“导出 PNG”是用户确认当前结果并生成文件的最终操作。

### 4.2 智能抠图

- 自动识别主体并生成初始 Alpha 蒙版；
- 模型推理在工作线程中执行；
- 显示加载模型和处理图片的状态；
- 推理失败时保留原图和已有编辑状态；
- 模型输出只作为基础蒙版，不直接破坏原始图片；
- 预留人像、通用物体及高质量模型切换接口。

### 4.3 选取色块

- 左键单击图片采集一个背景颜色；
- 可连续添加多个待移除颜色；
- 可框选区域并计算区域代表色；
- 颜色容差可调，修改后实时刷新预览；
- 支持删除单个颜色或清空全部已选颜色；
- 清空颜色选择不得影响画笔蒙版。

建议使用 RGB 距离或 Lab 色差作为初版匹配算法。复杂背景应优先使用智能抠图，不应依赖过大的颜色容差强行移除。

### 4.4 抠除与恢复画笔

- 抠除画笔将目标区域 Alpha 向透明方向修改；
- 恢复画笔将目标区域 Alpha 向可见方向修改；
- 画笔尺寸范围为 1～200 原图像素；
- 支持硬度和不透明度参数；
- 快速拖动时对采样点插值，避免笔迹断裂；
- 单次按下、拖动、释放构成一条撤销记录；
- 提供独立的“清空画笔修改”操作。

### 4.5 画布与预览

- 透明区域使用棋盘格表示；
- 鼠标滚轮以指针位置为中心缩放；
- 右键拖动平移画布；
- 左键执行当前激活工具；
- 支持适应窗口、100% 显示和重置视图；
- 支持原图、蒙版和结果三种查看模式；
- 支持按住空格临时查看原图；
- 状态栏显示缩放比例、原图尺寸和当前工具。

### 4.6 边缘优化

- 蒙版羽化；
- 蒙版收缩和扩张；
- 小范围孔洞填充；
- 可选边缘去色，用于减少白边、绿边等背景残色；
- 所有参数必须可恢复默认值，并支持预览。

## 6. 技术选型

| 层次 | 选型 | 作用 |
| --- | --- | --- |
| 桌面界面 | PySide6 | 窗口、工具栏、参数面板、线程通信 |
| 画布 | QGraphicsView/QGraphicsScene | 图片显示、缩放、平移和叠加绘制 |
| 基础图像处理 | Pillow | 图片读写、RGBA 合成、PNG 导出 |
| 高级图像处理 | OpenCV | 形态学、模糊、颜色空间转换、边缘处理 |
| 模型推理 | ONNX Runtime | 本地 CPU/GPU 模型执行 |
| 自动抠图适配 | rembg 或独立 ONNX 适配层 | 快速接入主体分割模型 |
| 打包 | PyInstaller | 生成 Windows 可执行程序 |
| 测试 | pytest、pytest-qt | 单元测试和界面交互测试 |

模型层必须通过统一接口隔离。业务代码不得直接依赖某个特定模型的输入尺寸、输出格式或下载目录，以便后续替换模型。

系统采用“界面层—应用层—领域层—基础设施层”分层结构。

```text
┌─────────────────────────────────────────────────────┐
│ UI 层                                               │
│ MainWindow / CanvasView / ToolPanel / ExportDialog  │
└────────────────────────┬────────────────────────────┘
                         │ 命令、事件、状态订阅
┌────────────────────────▼────────────────────────────┐
│ 应用层                                              │
│ ProjectController / CommandStack / TaskManager      │
└────────────────────────┬────────────────────────────┘
                         │ 编辑操作
┌────────────────────────▼────────────────────────────┐
│ 领域层                                              │
│ Document / MaskState / BrushEngine / Compositor     │
└────────────────────────┬────────────────────────────┘
                         │ 文件、模型、图像算子
┌────────────────────────▼────────────────────────────┐
│ 基础设施层                                          │
│ ImageIO / OnnxSegmenter / ModelStore / Exporter     │
└─────────────────────────────────────────────────────┘
```

### 7.1 UI 层

只负责展示状态和转发用户输入，不在事件处理函数中直接执行模型推理或大尺寸图像处理。

### 7.2 应用层

负责协调工具切换、文件生命周期、撤销重做、后台任务以及错误提示。

### 7.3 领域层

保存不可变原图、多个蒙版和编辑参数，并根据当前状态生成最终结果。

### 7.4 基础设施层

负责图片编解码、ONNX 推理、模型文件管理和最终导出。

## 8. 核心数据模型

### 8.1 ImageDocument

```python
@dataclass
class ImageDocument:
    source_path: Path | None
    original_rgba: Image.Image
    ai_mask: Image.Image
    color_mask: Image.Image
    erase_mask: Image.Image
    restore_mask: Image.Image
    selected_colors: list[SelectedColor]
    edge_settings: EdgeSettings
    revision: int
```

约束：

- `original_rgba` 加载后保持不可变；
- 所有蒙版均使用原图尺寸的 8 位 `L` 图；
- 0 表示完全透明，255 表示完全可见；
- 预览图属于渲染缓存，不作为下一次处理的输入；
- 所有坐标最终必须转换为原图坐标。

### 8.2 ViewState

```python
@dataclass
class ViewState:
    scale: float
    offset_x: float
    offset_y: float
    active_tool: ToolType
    overlay_mode: OverlayMode
```

视图状态与图片文档分离。平移或缩放不应创建图片编辑记录，也不应改变导出内容。

### 8.3 BrushSettings

```python
@dataclass
class BrushSettings:
    size_px: int = 20
    hardness: float = 1.0
    opacity: float = 1.0
```

`size_px` 始终代表原图像素，不能使用画布显示像素。

## 9. 蒙版合成规则

建议采用下列逻辑生成最终 Alpha：

1. 从 AI 蒙版开始；若尚未运行智能抠图，则使用全白蒙版。
2. 应用颜色抠除蒙版，降低匹配背景区域的 Alpha。
3. 应用抠除画笔，降低人工擦除区域的 Alpha。
4. 应用恢复画笔，提高人工恢复区域的 Alpha。
5. 执行收缩、扩张、孔洞修复和羽化。
6. 将最终 Alpha 与不可变原图的 RGB 通道合成。

概念公式如下：

```text
base       = ai_mask 或 full_white_mask
removed    = min(base, color_mask, inverse(erase_mask))
restored   = max(removed, restore_mask)
final      = edge_refine(restored, edge_settings)
result     = original_rgb + final_alpha
```

恢复画笔的优先级高于自动抠图和颜色抠除，使用户能够找回被算法误删的主体区域。

## 10. 坐标转换与画笔绘制

画布坐标转换为原图坐标：

```text
image_x = (canvas_x - offset_x) / scale
image_y = (canvas_y - offset_y) / scale
```

转换后应进行边界裁剪，并保留浮点精度直到实际写入蒙版。

为了避免快速拖动画笔产生断点，相邻输入点之间按照不超过 `brush_size / 4` 的步长插值。一次笔画的流程为：

1. 鼠标按下时保存笔画前蒙版快照或差异区域；
2. 鼠标移动时执行坐标转换和插值绘制；
3. 仅刷新受影响的局部区域；
4. 鼠标释放时提交一个撤销命令；
5. 取消操作时恢复笔画前状态。

## 11. 自动抠图服务接口

```python
class Segmenter(Protocol):
    @property
    def name(self) -> str: ...

    def load(self) -> None: ...

    def predict(
        self,
        image: Image.Image,
        progress: Callable[[int], None] | None = None,
        cancel_token: CancelToken | None = None,
    ) -> Image.Image: ...
```

接口要求：

- 输入为 RGBA 或 RGB 原图；
- 输出为与原图尺寸一致的 `L` 蒙版；
- 内部自行处理缩放、归一化和输出还原；
- 支持取消和进度通知；
- 模型加载失败时抛出可识别的领域异常；
- 同一模型会话应复用，避免重复加载。

## 12. 撤销与重做

采用命令模式维护编辑历史。建议支持的命令包括：

- `AddSelectedColorCommand`
- `RemoveSelectedColorCommand`
- `ChangeToleranceCommand`
- `BrushStrokeCommand`
- `ApplyAiMaskCommand`
- `ChangeEdgeSettingsCommand`
- `ClearMaskCommand`

画笔命令优先保存受影响矩形内的前后差异，而不是复制整张大图。历史记录默认限制为 50～100 步，并根据占用内存设置上限。

模型推理结果应作为一个原子命令写入历史。任务取消或失败时不得产生半完成记录。

## 13. 性能设计

### 13.1 预览与导出分离

- 编辑期间可以生成降采样预览；
- 蒙版编辑始终记录在原图尺寸空间；
- 导出时使用原图和完整尺寸蒙版重新合成；
- 不得直接把低分辨率预览保存为最终文件。

### 13.2 后台任务

以下操作必须放入工作线程：

- 模型加载；
- 智能抠图推理；
- 超大图片全尺寸边缘处理；
- 大尺寸 PNG 编码。

工作线程通过信号发送进度和结果，禁止直接修改 Qt 控件。

### 13.3 缓存策略

- 缓存当前模型会话；
- 缓存最近一次合成预览；
- 参数未变化时不重复计算蒙版；
- 画笔期间优先局部刷新，笔画结束后执行完整一致性刷新。

## 15. 异常处理

| 场景 | 处理方式 |
| --- | --- |
| 不支持或损坏的图片 | 显示明确错误，不替换当前文档 |
| 模型文件不存在 | 引导下载或选择模型，不影响手动工具 |
| 模型加载失败 | 记录日志并允许重试或切换 CPU |
| 推理内存不足 | 提示降低模型质量或图片预处理尺寸 |
| 导出路径不可写 | 保留编辑状态，允许重新选择路径 |
| 用户取消后台任务 | 安全终止任务并恢复任务前状态 |
| 超大图片 | 提示内存风险，预览降采样，导出保持原尺寸 |

日志不得记录完整图片数据，也不得上传文件路径或用户图片。

## 17. 验收标准

首个可交付版本需满足：

1. 支持常用图片格式导入和透明 PNG 导出。
2. 右键平移、滚轮缩放、左键工具操作无冲突。
3. 支持智能抠图、颜色抠除、抠除画笔和恢复画笔。
4. 1px 画笔在任意缩放倍率下可准确编辑原图像素。
5. 任意预览刷新均从不可变原图和当前蒙版状态重新生成。
6. 清除某类编辑后，先前被误删的原始像素可以正确恢复。
7. 至少支持 50 步可靠的撤销和重做。
8. 智能推理期间界面不阻塞，并可显示进度或忙碌状态。
9. 导出尺寸与原图一致，透明通道正确。
10. 关键交互由自动化 GUI 测试覆盖，不以语法检查代替交互验证。

## 19. 主要风险与应对

| 风险 | 影响 | 应对方式 |
| --- | --- | --- |
| 模型对发丝或透明物体效果不稳定 | 自动结果不可直接使用 | 提供恢复画笔、羽化和模型切换 |
| 大图占用大量内存 | 卡顿或崩溃 | 降采样预览、局部刷新、内存上限提示 |
| GPU 环境差异大 | 安装和运行失败 | 默认支持 CPU，GPU 作为可选加速 |
| 模型包体较大 | 分发困难 | 首次启动下载或提供独立模型包 |
| 预览与导出不一致 | 用户结果不可控 | 使用同一蒙版管线，全尺寸重新合成 |
| 工具模式冲突 | 误擦除或误取色 | 工具互斥、光标提示、GUI 事件测试 |

## 20. 后续扩展

基础版本稳定后，可按优先级增加：

1. 批量抠图和批量导出；
2. 自动裁切及留白设置；
3. 替换纯色、渐变或图片背景；
4. 项目文件保存，保留蒙版和编辑历史；
5. 前景/背景标记辅助分割；
6. 人像发丝专用精细模型；
7. 快捷键自定义；
8. 插件式模型管理；
9. 命令行批处理接口；
10. 视频关键帧和时序蒙版。

## 21. 实施结论

第一阶段应优先建立可靠的蒙版编辑内核，而不是把主要精力投入模型数量。只要原图不可变、所有编辑基于原图尺寸蒙版、预览和导出共用同一合成逻辑，后续替换智能模型、增加批处理或扩展边缘算法都不需要推翻现有架构。

推荐按 M1 → M2 → M3 → M4 → M5 → M6 的顺序实施：先保证手工可控和导出正确，再完善颜色抠除与编辑历史，随后接入自动模型，最后处理边缘质量和应用分发。
